## 基础知识
1. 基本概念
	1. 抽象：从众多事物中抽取出共同的，本质性的特征
	2. 体系架构：应用系统的组成结构，应用系统规划设计的目标之一是推导出应用系统体系架构示意图。
	3. 模式：面向一般问题的解决方法
	4. 关注点：一个特征或一个行为，采用分而治之的策略分解问题
	5. 模块化：关注点分离的常见表现
	6. 信息隐蔽原则：封装
	7. 功能独立：关注点分离，模块化，抽象和信息隐蔽的直接产物
		1. 高内聚，低耦合
	8. 求精：自顶向下的规划设计策略   求精就是一个细化的过程
		1. 抽象和细化是互补的概念，细化在规划设计过程中揭示底层细节。
	9. 重构：重新组织的技术，简化应用系统及组成部分的规划设计单功能保持不变
2. 基础架构
	1. 应用系统的分层体系  从上至下
		1. 界面交互层
		2. 业务处理层
		3. 数据处理层
		4. 数据存储层
	2. 架构分类：数据为中心，客户机/服务器架构，组件分布架构
		1. 客户机/服务器架构:
			1. 两层：结构简单，操作性能好
			2. 两层：有利于系统维修，实现难度大
			3. 浏览器：无须对客户机维护，但稳定性低于传统的
		2. 组件分布：（中间层架构）
			1. CORBA：与机器无关的分布式对象准则
			2. DCOM：接口，DCOM的通用性不如CORBA
			3. EJB：基于java的分布式对象模型

2. 常见的生命周期模型和特点
	1. 瀑布模型 阶段间具有顺序性和依赖性 推迟实现的观点 质量保证的观点   
			2. V模型   瀑布模型的变种 描述测试活动如何与分析和设计活动相关联
			3. 迭代模型 演化建设和增量建设
				1. 优点：逐步的增加应用系统的功能可以使用户有较为充足的时间学习和适应新产品，从而减少全新应用系统可能给用户带来的冲击
				   建设失败的风险低   优先级最高的服务首先交付
			4. 敏捷方法
				1. 敏捷宣言   个体互动  工作软件 客户合作 响应变化
		2. 生命周期模型的通用活动：需求-设计-构造-流程-标准
3. 两种结构化的体系结构定义方法
   自顶向下，逐步求精，以模块为中心
	1. 面向数据流的    多在概要阶段使用
		1. 变换型数据流： 输入->处理->输出
		2. 事务型数据流：非数据变换的处理    将输入的数据流分散许多数据流，选择其中一个路径来执行
	2. 面向数据结构的  通常在详细设计阶段使用
		1. Warnier方法仅考虑输入数据结构
		2. Jackson方法不仅考虑输入数据结构，还考虑输出数据机构
		   顺序型，选择型，循环型
	3. 表示应用系统体系结构的图形工具
		1. 层次图  上方模块调用下方模块
		2. 结构图

## 主要过程
1. **应用系统规划的主要过程**  出行细粉机
	1. 初步调研
	2. 可行性分析
	3. 详细调研
	4. 系统分析
	5. 系统设计
2. 初步调研的具体内容
	立足于宏观  (该换戏台子)
	1. 组织概况
	2. 组织环境
	3. 现行系统概况     
	4. 各方面对新系统的态度
	5. 系统研制工作的资源情况
3. **可行性研究的步骤和内容**
	1. 步骤  复习新题 房间开写
		1. 复查系统目标和规模
		2. 研究目前正在使用的系统
		3. 导出新系统的高层逻辑模型
		4. 重新定义问题
		5. 导出和评价供选择的方案
		6. 推荐一个方案并说明理由
		7. 草拟开发计划
		8. 书写文档并提交查看
	2. 内容：经济可行性，技术可行性，管理可行性，社会可行性
	3. 必要性：组织内部要求   管理人员的分析
4. 可行性研究报告的主要内容
   任务-目标-概括-方案-研究-结论
5. 详细调研的范围和原则
	1. 调研的对象：现行系统
	2. 原则： 主公圈粉自用
		1. 主动沟通和友善的工作方式
		2. 工程化的工作方式
		3. 全面与重点相结合
		4. 分析系统有无改进的可能
		5. 自顶向下全面展开
		6. 用户参与
6. **详细调研的内容**
	1. 收集信息  准确性 全面性 时效性
	2. 系统需求建模   需要系统做什么
	3. 需求的优先级划分 最重要的事
	4. 构建系统原型，检验可行性并发现问题  
	5. 产生和评估候选方案
	6. 和管理部门一起复查各种建议
7. 系统分析的过程和方法
	1. 产出：系统说明书
	2. 过程：
		1. 问题分析   原型法 JAD会议 观摩法
		2. 需求分析 
		3. 需求定义
8. 系统说明书（需求规格说明书）内容
	1. 引言
	2. 概述
	3. 实施计划
9. **评价与衡量系统设计目标实现程度的主要指标**(重点)

## 软件工厂
是一种软件开发的组织和管理模式
与传统软件开发比较：开发过程更标准化，规范化，开发工具更完备，自动化程度高，开发人员分工更合理，协作更高效，注重知识共享和经验服用，减少重复工作

	2. 资源部署
	3. 业务管理
	4. 体系保障
